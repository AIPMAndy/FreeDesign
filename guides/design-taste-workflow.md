## 一句话工作流

**先明确场景 → 找 3 个视觉对标 → 拆结构与设计规则 → 自己重组 → 做真实设备验证 → 再交付。**

| 当前任务 | 优先打开 | 最终输出 |
| --- | --- | --- |
| AI 产品官网或 Landing Page | 02 → 06 → 09 | 首屏方案、页面层级、Token、响应式稿 |
| 小红书 / X / 公众号封面 | 04 → 05 → 06 | 版式草图、标题层级、可读性验证 |
| App / 小程序 / 后台 | 03 → 05 → 09 | 关键流程、空状态、组件与交互规范 |
| 视频、产品宣传片 | 07 → 04 → 08 | 分镜、视觉参考板、镜头与节奏说明 |
| 品牌视觉升级 | 01 → 04 → 05 | 情绪板、品牌字体和色彩规则 |

## 10 分钟审美拆解法

对每张参考图，不只说“好看”，而是写出可以被验证的设计决策：

1. **目标**：这页到底要让用户看见、理解或执行什么？
2. **信息层级**：前 3 秒会注意哪里？标题、副标题、按钮分别承担什么？
3. **版式**：栅格、留白、对齐、重心、节奏有没有明确规则？
4. **字体与颜色**：最多几级字重？强调色是否真的传递优先级？小屏是否仍易读？
5. **交互与状态**：手机上怎么展示？加载、空状态、错误态是否完整？
6. **可复用产出**：提炼 3 条规则，而不是搬运截图；用自己的内容重新验证。

**记录模版**（每次填一张卡）：

```text
项目 / 要解决的问题：
参考链接（最多 3 个）：
用户与使用场景：
可借鉴的 3 条规则：
不适合本项目的 2 个点：
下一步可测试的改动：
验收标准（例如 375px 手机宽度下，主标题完整可读）：
```

## 给 AI / Codex / Workbuddy 的设计提示词

```text
我要做【产品/页面/海报/视频】，目标用户是【人群】，
最重要的用户动作是【单一目标】，主要发布平台是【平台/画幅】。

请先读取我提供的 2–3 个合法可访问的视觉参考，
不要照搬他人的标志、文案、插画或完整界面。

第一步：每个参考抽取可解释的设计规则：
版式网格、留白比例、字体层级、配色角色、视觉锚点、交互反馈。
第二步：对规则按我的场景取舍，明确不采用什么以及理由。
第三步：先给 2 套低保真布局，再选 1 套实现。
第四步：输出组件结构、设计 Tokens 和移动端适配要求。
第五步：按可读性、对比度、信息层级、真实内容溢出做 QA。
输出应能直接复用，避免只给“高级感”“科技感”之类的形容词。
```

## 一周训练：从收藏夹变成判断力

| 天数 | 练习 | 可验收成果 |
| --- | --- | --- |
| Day 1 | 从第 01 类挑 3 种完全不同的风格 | 1 张情绪板 + 3 条差异 |
| Day 2 | 拆 3 个 Landing Page 的首屏 | 标注层级、留白、CTA |
| Day 3 | 对比 3 套同类 App 流程 | 一张流程对比表 |
| Day 4 | 选 2 张品牌海报做视觉拆解 | 字体、主视觉、配色规范 |
| Day 5 | 完成字体配对与对比度检查 | 字体和色彩 Token |
| Day 6 | 研究 3 条短片或交互动效 | 关键帧与节奏表 |
| Day 7 | 把前 6 天的规则用于自己的项目 | 1 个可展示的成品 + QA 结果 |

## 使用边界与维护规则

- **尊重创作者**：学习排版规律和设计方法，不把参考作品当成无版权模板；商用素材、字体、动效和截图需另行核对授权。
- **区别展示与实现**：第三方网站可能需要注册、付费或有流量限制；本导航不承诺全部免费。
- **不盲目增量**：发现新站点之前，先查重复项、链接有效性、清晰用途与是否有更好的现有替代。
- **更新真实状态**：某个站点改名、关站、重定向或调整收费时，保留更正记录，不用陈旧结论冒充实时测评。
